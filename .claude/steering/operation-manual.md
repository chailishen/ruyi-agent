# 操作手册编写规范

## 目标读者
项目验收评审专家。手册需要简洁实用，重点展示功能完整性和操作流程。

## 文档结构（每个模块）

```markdown
# {角色端} - {模块名称}

## 功能概述
（1-2句话说明该模块用途）

## 操作步骤

### 步骤1：{操作描述}
{具体操作说明}

![步骤描述](../实训项目截图/{角色端}/{模块名}/{文件名}.png)

### 步骤2：{操作描述}
...

## 预期结果
（操作完成后用户看到什么）
```

## 写作风格
- 使用"点击"、"输入"、"选择"等动词开头描述每个步骤
- 每个步骤只包含一个动作，不要合并多个操作
- 不写技术实现细节，只写用户可见的操作
- 语言简洁明了，面向非技术人员

## 图片引用规则
- 使用相对路径引用截图：`![描述](../实训项目截图/{角色端}/{模块名}/{文件名}.png)`
- 如果截图文件名是UUID，根据图片内容为步骤命名
- 如果截图文件名是中文描述，直接使用作为步骤参考
- 按操作���辑顺序排列截图（概览→列表→详情→编辑）

## 图片分析要求
- 仔细观察截图中的导航栏、按钮、表单、列表等UI元素
- 根据截图内容推断操作顺序
- 标注关键交互元素的位置和名称
- 如有多张截图，推断它们之间的操作流转关系

## 输出规则
- 文件保存到：`操作手册/{角色端}_{模块名}.md`
- 文件编码：UTF-8
- 完成后提示用户可运行 `./scripts/md-to-word.sh` 转换为 Word
