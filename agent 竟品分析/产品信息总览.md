## 产品详情

### 1. CodeBuddy WorkBuddy

**定位**

WorkBuddy 是 CodeBuddy 产品体系下的本地 AI 工作台。官方文档中的“新建任务栏”被定义为本地任务统一入口，用户可从这里创建任务、设置工作目录、选择模型和技能。

**核心能力**

- 工作模式：提供 Ask、Craft、Plan 三种模式。
- Ask：仅问答与信息查看，不修改文件，适合了解内容和确认需求。
- Craft：直接执行任务并修改文件，适合文档生成、表格处理、文件整理。
- Plan：先生成执行计划，确认后再操作，适合多步骤任务和需要审阅改动范围的工作。
- 模型切换：文档列出 MiniMax M2.5、智谱 GLM-5、Kimi K2.5、DeepSeek V3.2、腾讯混元等模型，并按 Excel/数据分析、长流程、视觉任务、日常问答、中文文档等场景给出建议。
- 工作目录：建议用户先设置工作目录，系统将在该目录中读取和保存文件；未指定路径时，新建任务会自动创建独立目录。
- 技能系统：内置 20+ 技能包，覆盖文档处理、数据报表、海报设计、文件整理等场景；兼容 OpenClaw 社区技能导入，也支持用自然语言创建自定义技能。
- 连接器：支持连接第三方应用以扩展 AI 能力。
- 权限管理：包含默认权限和完全访问权限；涉及敏感操作、文件修改或工作空间外执行时，默认权限会要求用户确认。
- 多任务：每个对话对应独立任务，任务之间互不影响，维护独立工作空间与上下文；执行中任务显示在左侧边栏，支持多任务并行。

**典型场景**

- 文档生成与编辑
- 表格处理和数据分析
- PPT 生成
- 海报生成
- 自动化报表
- 文件整理
- 连接外部应用后的跨工具任务

**待补充/待核验**

- WorkBuddy 与 CodeBuddy IDE、插件、CLI 的关系边界
- 账号体系、积分、定价和企业版能力
- 数据发送到模型服务商的范围
- 连接器列表和实际可用性
- Skills 创建、安装、调试的体验成本

### 2. EasyClaw

**定位**

EasyClaw 官网定位为“开箱即用的 AI 龙虾”，强调集成主流模型、一键安装、无需配置，让 AI 自动帮用户干活。页面标题明确写到“零配置桌面端 AI 智能体（基于 OpenClaw）”。

**产品形态**

- Windows 10+ 下载
- macOS 11+ 下载
- EasyClaw Cloud Edition：云端专属主机，强调 24/7 在线、注册即用
- 企业版：官网有企业版入口

**核心能力**

- 场景覆盖：电商运营、股票投资、内容创作、数据采集、信息简报、数据分析等。
- 聊天工具接入：官网列出 EasyClaw App、WeChat、Feishu、WeCom、Telegram、QQ、WhatsApp、Discord、DingTalk、Slack、Google Chat、Mattermost、Microsoft Teams、LINE、Matrix、Signal、iMessage 等入口。
- 专家员工：内置投资、运营、创作、数据、法务、教育等行业场景的专家员工。
- 技能组合：各类专家可搭配技能使用，如选股、复盘、数据分析、爆款写作、AI 润色、PPT 制作、网页数据采集等。
- 自动化能力：官网竞品对比区域提到本地文件读写、终端命令执行、系统级电脑操作、浏览器操作等能力。
- Agent 生态：页面强调结构化长期记忆、人格定制、定时自动任务、Skills 生态、多 Agent 协作等方向。
- 模型支持：官网称支持 15+ 模型和自定义模型，也提到可接入本地模型或其他 API。
- 安全能力：官网提到本地沙盒安全防护、企业级安全防护、数据备份与迁移等。

**典型场景**

- 多店铺运营数据日报、库存预警、差评提醒、自动回复咨询
- 股票盯盘、选股、持仓监控
- 公众号选题、写作、发布
- 爆款视频分析和竞品拆解
- PPT 汇报提案生成
- 行业资讯简报
- 小红书笔记持续产出

**待补充/待核验**

- 免费版、云端版、企业版的能力差异
- 聊天渠道接入方式和授权安全边界
- 15+ 模型的实际列表、可用地区和价格
- Skills 市场规模、安装门槛和开发者生态
- 与 OpenClaw 的关系：上游开源、二次封装还是服务化发行

### 3. QClaw

**定位**

QClaw 官网定位为“微信远程办公 AI 助手”，由腾讯出品。官网元信息描述其为个人 AI 助手，可通过微信远程整理文件、执行复杂任务，适配办公、创作、开发等多场景。

**产品形态**

- macOS Apple 芯片版
- macOS Intel 芯片版
- Windows 版
- 官网结构化数据标注 operatingSystem 为 macOS、Windows，applicationCategory 为 ProductivityApplication，价格字段为 0 CNY。

**核心能力**

- 自动部署，打开即用：支持 Mac 和 Windows，内置国产模型，并支持切换自定义模型。
- 微信直接对话，远程操控：通过微信关联，用户可随时远程让 AI 执行任务。
- Skills 生态：官网脚本文案提到支持 Skills 市场，如 ClawHub、GitHub 等生态。
- 持续记忆：强调记住用户偏好和上下文，逐渐成为专属助手。
- 本地部署：强调可直接操控文件、浏览器、邮件，不只是聊天。

**快速上手路径**

1. 下载安装：支持 Mac 和 Windows，一键安装。
2. 扫码绑定微信：打开 QClaw 后扫码关联微信。
3. 发指令执行：通过微信或电脑发送消息，QClaw 开始执行任务。

**官网展示场景**

- 远程操作电脑文件或网页，例如打开桌面 Excel 并计算数据。
- 整理电脑资料并生成摘要。
- 设置每日天气定时提醒。
- 记录用户偏好，例如邮件语气和结尾格式。
- 自动创建 GitHub 项目、写代码、生成 README。
- 检索论文、整理引用、生成文献综述。

**待补充/待核验**

- 微信绑定的技术流程、权限边界和隐私说明
- 是否支持 QQ、企业微信或其他 IM 渠道
- Skills 市场具体规模和安装方式
- 模型额度、价格、免费策略和限流规则
- 本地执行时的文件访问、浏览器操作、邮件操作授权机制

### 4. QoderWork

**定位**

QoderWork 是 Qoder 的桌面端智能工作助手，将 Qoder 的 Agent 能力从代码领域扩展到日常工作场景。官方文档强调它不是只回答问题，而是通过自然语言对话交付文件整理、数据处理、文档生成等任务结果。

**核心能力**

- 自主规划执行：理解复杂任务意图，自动拆解执行步骤。
- 过程可控：任务进展可见，遇到问题会主动沟通。
- 能力可扩展：内置多种主流 MCP 工具，支持自定义 Skills，覆盖多样化工作流。
- 本地安全运行：文件操作在本地完成；只能访问用户明确授权的工作目录，未授权内容如需访问会征求同意。
- 账号与价格：支持 Qoder 账号登录，与 Qoder 账号共享 Credits。

**典型场景**

- 文件整理：识别文件类型并整理项目文件。
- 照片管理：按时间、地点、主题分类整理本地照片。
- 数据分析：分析数据结构，生成统计报表与可视化图表。
- 文档创作：撰写报告、制作演示文稿、处理表格数据。
- 研究整合：汇总多源信息并提炼关键洞察。

**安全/隐私说明**

官方 FAQ 表示：QoderWork 的文件操作在本地完成，但为了实现 AI 理解和分析，相关文本内容会发送至大模型 API 服务商。

**待补充/待核验**

- QoderWork 与 Qoder Desktop、CLI、Cloud Agents、移动端/网页版的协同方式
- Credits 消耗规则和套餐价格
- MCP 工具清单和第三方连接器列表
- 自定义 Skills 的开发、调试和分享机制
- 与代码 Agent 能力之间的复用程度

### 5. MiniMax Agent / MiniMax Code

**定位**

MiniMax 官网把 MiniMax Code 定位为“built for MiniMax models”的 coding harness，同时在 MiniMax Agent Team 官方博客中介绍了 MiniMax Agent 的整体升级。其产品方向已经从单一聊天或代码生成，扩展到面向长任务的 Agent Team、多角色协作、记忆和 Skills。

**产品形态**

- MiniMax Agent / MiniMax Code：官网提供 Try Code、Desktop 等入口。
- Agent Team：在桌面端可并行运行多个 Agent，创建不同角色，并组成团队处理复杂任务。
- 订阅与额度：官方博客提到 TokenPlan 和 Agent Plan 合并，CLI、API、Agent 共用 Credits。

**核心能力**

- Agent Team：一个主 Agent 接收目标后，可将复杂任务拆成并行子任务，由不同 Agent 分工执行。
- 角色分工：官方博客举例 Leader、Worker、Verifier 等角色，强调从“能产出”走向“可交付”。
- 长任务执行：面向长文档、研究、编码、办公文档写作等长链路任务，强调后台执行和状态汇报。
- 技能与记忆：官网提到 custom skills、memories、schedules；博客也提到任务经验可沉淀到 memory 和 Skills。
- IM 异步场景：官方博客专门讨论通过 IM 驱动 Agent 时的异步执行、快速响应和后台任务状态。
- Coding Harness：强调分支、沙盒、diff、测试、审查和可复现执行记录，适合与 Codex/Qoder 的代码 Agent 体系对照。

**典型场景**

- 多角色协作完成长文档、研究报告、HTML/Markdown 交付
- 编码任务中的开发、测试、审查分工
- 并行信息检索和事实核验
- 办公文档、表格、PDF 的流水线式生成和校验
- 通过 IM 或聊天入口发起长任务，后台持续执行

**待补充/待核验**

- MiniMax Agent 与 MiniMax Code 的具体产品边界和入口差异
- Desktop 客户端支持平台、安装流程、国内账号可用性
- Agent Team 在普通用户套餐中的开放范围和额度消耗
- 文件、本地命令、浏览器、外部系统访问的权限设计
- Skills 创建、安装、分享、调试的实际体验

### 6. Kimi Work / Kimi Claw / Agent Swarm

**定位**

Kimi 体系已经从通用聊天助手扩展到 Agentic AI workspace。官方产品页中，Kimi Work 被定义为面向知识工作者的 AI Desktop，本地连接文件、可进行浏览器自动化，并支持长期运行；Kimi Claw 则是云端部署 OpenClaw 的 24/7 个人 AI 助理；Agent Swarm 体现多 Agent 并行扩展能力。

**产品形态**

- Kimi Work：Windows 与 macOS 桌面端，定位本地 Agent。
- Kimi Claw：云端 OpenClaw，强调一键部署、24/7 在线、云存储和 ClawHub Skills。
- Kimi Web / Kimi 功能页：Slides、Websites、Docs、Deep Research、Sheets、Agent Swarm 等任务入口。
- Kimi Code / WebBridge：分别面向代码 Agent 和浏览器自动化场景。

**核心能力**

- 本地文件连接：Kimi Work 可挂载本地文件夹，处理本地 PDF、文档、数据和输出文件。
- 浏览器自动化：WebBridge 支持像人一样点击、滚动、提取数据和执行多步网页任务。
- 定时任务：Kimi Work 使用内置 Cron 引擎，支持 LLM Agent Calls、Python/Shell 执行等定时自动化。
- 多 Agent 协作：Agent Swarm 可把复杂任务拆给多个专门 Agent 并行处理，用于大规模研究、文件处理和长文写作。
- 云端 OpenClaw：Kimi Claw 提供 24/7 在线、持久记忆、自定义人格、定时任务、40GB 云存储和 5,000+ ClawHub Skills。
- 办公交付：Kimi Work 产品页提到研究完成后可转换为 PPT 或 Excel 等办公成果。
- 金融数据：Kimi Work 产品页提到内置 A 股、港股、美股相关数据源，用于财报、异动分析和表格核对。

**典型场景**

- 搜索本地目录中的 PDF，整理为摘要文档
- 定时生成每日简报、周报、提醒或数据处理脚本
- 自动浏览网页、抓取数据、填写表单、保存结果到 Excel
- 使用 Agent Swarm 生成长篇研究、文献综述、批量资料整理
- 用 Kimi Claw 运行 24/7 信息雷达、内容创作、数据可视化和云端归档

**待补充/待核验**

- Kimi Work 国内账号、会员档位和下载入口的实际可用性
- 本地目录授权、文件修改、代码执行和 Yolo 模式的安全边界

### 建议设计的统一体验任务

| 任务类型 | 测试任务 | 观察点 |
| --- | --- | --- |
| 文件整理 | 给一组混乱文件，要求按项目分类并生成摘要 | 文件访问授权、分类准确度、输出可读性、是否误操作 |
| 表格分析 | 给 Excel/CSV，要求统计、可视化并生成报告 | 数据读取、图表生成、解释质量、文件保存路径 |
| 文档/PPT | 输入主题和资料，要求生成报告或演示稿 | 模板质量、结构质量、可编辑性、格式稳定性 |
| 浏览器任务 | 要求打开网页、采集信息并整理 | 浏览器控制能力、反爬/登录处理、引用来源 |
| 定时任务 | 设置每日简报或天气提醒 | 调度可靠性、通知渠道、取消/修改方式 |
| IM 远程调用 | 通过微信/飞书/其他 IM 下发任务 | 消息入口体验、远程执行延迟、权限确认方式 |
| 技能生态 | 安装或创建一个自定义 Skill | 门槛、调试体验、复用性、社区资源 |
| 安全边界 | 尝试访问工作目录外文件 | 是否明确询问授权、是否有日志、是否可回滚 |
| 多 Agent 协作 | 要求并行调研 10 个竞品并生成带来源的对比报告 | 是否自动拆分、角色是否清晰、能否交叉核验、最终汇总质量 |
| 长任务恢复 | 中途关闭客户端或断网后继续任务 | 状态持久化、失败恢复、用户提示、产物是否丢失 |
| 企业协同 | 要求把分析结论转成任务并分派给不同角色 | 组织权限、任务流转、通知、审批、审计记录 |
| 手机/GUI 操作 | 让 Agent 在手机或网页中完成多步骤表单/查询任务 | 操作准确性、误触防护、高风险确认、可中断性 |

### 初步关注问题

- “本地执行”与“文本发往模型 API”之间的边界是否被清晰解释。
- 远程控制电脑的便利性与安全风险如何平衡。

- 多 Agent 是否只是多个角色提示词，还是具备独立上下文、工具权限、状态机、验证和恢复机制。
- 云端 24/7 Agent 的存储、费用、任务调度、数据边界和退出迁移机制是否清晰。
- 企业 Agent 是否真正接入业务系统并能推动流程，还是停留在报表/建议层。
- 手机/GUI 操作型 Agent 对误操作、支付、下单、发送消息等高风险动作如何拦截。
- 多模型选择是否真的面向任务优化，还是主要作为营销卖点。
- 企业版是否提供权限审计、数据隔离、组织管理、统一模型网关和合规能力。
