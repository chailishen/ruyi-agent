# 工作日志管理

本目录由 `work-log-manager` 插件使用，采用 Markdown 文件保存每日流水、长期背景信息和正式周报。

## 目录约定

- `daily/YYYY/MM/YYYY-MM-DD.md`：每日工作流水，保留原始输入和整理条目。
- `context/*.md`：长期工作背景、项目说明、术语和周报写作约束。
- `templates/*.md`：日报和周报模板。
- `weekly/YYYY/*.md`：生成后的正式周报。
- `state/weekly-report-state.json`：记录上一次周报范围，用于默认续写下一期。

## 日志更新

说“记录一下”“补充今天日志”“把 5 月 20 日的日志补一下”等请求时，插件会：

- 根据输入识别日期；没有日期时使用当天日期。
- 根据输入识别项目；不明确时使用“未指定项目”。
- 在每日文件中同时写入“原始输入”和“整理条目”。

## 周报编写

说“帮我写本周周报”或指定日期范围时，插件会：

- 读取日期范围内的每日流水。
- 读取 `context/*.md` 和公司周报模板。
- 按“个人周报｜姓名｜岗位｜日期”的公司模板生成正式周报。
- 保存到 `weekly/YYYY/` 并更新状态文件。

未指定日期范围时，默认从上一次周报结束日期的下一天开始，覆盖 7 天；如果还没有状态文件，则使用截至当天的最近 7 天。

## 公司周报模板要求

- 每周只写 3-8 件重点事项。
- 本周事项进展必须包含：事项、类别、目标结果、当前状态、进度、本周推进、卡点/风险、下周动作、需要支持。
- 当前状态只能是：正常、风险、阻塞。
- 关键结果只写已经完成且有实际价值的结果。
- 下周计划必须有目标结果和截止时间。
- 需要协调时必须写清楚背景、需要领导做什么和建议方案。
