# 周报写作约束

- 面向公司系统提交，语言正式、客观、简洁。
- 使用公司模板结构：个人周报、本周事项进展、本周完成的关键结果、当前卡点与风险、下周计划、需要协调、其他补充。
- 每周只写 3-8 件重点事项，不要求面面俱到。
- 不写流水账，不写空泛的“沟通中、推进中、处理中”；必须写清楚推进到哪一步。
- 每件重点事项必须写目标结果，例如：完成 Demo、进入评审、客户确认试用、完成上线、输出报告。
- 事项类别只能从“售前、产品、研发、算法、交付、其他”中选择。
- 当前状态只能填写“正常、风险、阻塞”。
- 有风险时必须写清楚影响什么，例如：影响交付、影响演示、影响验收、影响成单、影响上线。
- 需要支持时必须写清楚需要谁、在什么时间前、协调什么事情。
- “本周完成的关键结果”只写已经完成、对项目有实际价值的结果，不写过程流水账。
- “下周计划”必须有目标结果和截止时间。
- 多项目内容可以拆成多条事项，但必须保持事项、目标、风险、下周动作一一对应。
- 保留事实边界，不将计划写成已完成，不将尝试写成稳定成果。
- 日志信息不足时，在“待补充信息”中列出。

## 状态定义

- 正常：按计划推进，无明显风险。
- 风险：存在不确定性，可能影响进度、质量、交付或客户决策。
- 阻塞：已经卡住，需要他人或领导介入。
