## 原文导语（文章正文文字部分）

很多企业一聊 AI，就会直接问：

- 「我们是不是要做一个 Agent？」
- 「有没有现成工具可以直接买？」
- 「能不能先搭一个大系统？」

但真正落地时，最容易踩坑的地方恰恰是：**先做系统，再找场景。**

企业 Agent 不是一个聊天框，也不是一个「万能 AI 助手」。  
它本质上是一套能连接 **业务场景、数据底座、企业方法论、AI Skill 和工作流程** 的系统化能力。

尤其在营销场景里，Agent 要想真正有用，不能只接大模型，还必须接入企业自己的数据和营销判断逻辑。

## 核心要点整理

### 一句话结论

> **企业 Agent 的关键不是模型，而是系统能力。**  
> 真实场景 + 稳定数据 + 业务方法论 + AI Skill + 试点验证 = 企业级 Agent 能力

### 4 个核心原则

1. **场景先行**：先定义业务场景，再验证真实价值  
2. **数据为底座**：让 Agent 建立在可用、可管、可调用的数据之上  
3. **方法论驱动**：把经验沉淀为可复用的流程、规则与 Prompt  
4. **小步快跑**：从试点开始，边跑边优化，逐步扩展  

### 企业智能中枢六要素（图 01）

- 业务场景（需求分析 / 优先级 / 价值评估）
- 方法论（流程梳理 / Agent 设计 / 提示工程 / 评估迭代）
- Skill（技能库 / 工具集成 / 插件扩展 / 持续优化）
- 底层支撑（大小模型 / 向量库 / 知识库 / 基础设施与安全）
- 系统入口（Web·PC / 企微钉钉 / 移动小程序 / API）
- 数据（资产梳理 / 质量治理 / 接入整合 / 安全权限）

### 12 步流程（图 03）

1. 场景定义  
2. 价值判断  
3. 数据源选择  
4. 数据需求定义  
5. 数据底座搭建  
6. 数据治理  
7. 方法论沉淀  
8. Skill 工作流设计  
9. 系统接入  
10. 小场景试点  
11. 效果度量  
12. 迭代扩展  

### AI Skill 设计四步（图 04）

1. 输入参数  
2. 数据调用  
3. 分析逻辑  
4. 输出结果  

### 数据源选型（图 05）

| 类型 | 适用 |
|------|------|
| 公开数据 / Skills | 低频探索 |
| 稳定 API | 小规模测试 |
| 企业级数据库 | 高频稳定调用 |
| 平台工具 | 标准能力补充 |

口诀：**小场景用 Skills + API，大规模用企业级数据库。**

## 对我的启发（个人笔记位）

- 与鲁信「先场景后工具」、海尔「嵌进流程」同向：反对先买平台再找场景。
- 「Skill = 输入参数 → 数据调用 → 分析逻辑 → 输出结果」可直接用作自家技能模板。
- 数据源分层选型对营销/投研类 Agent 很实用，避免一上来就接全量数仓。
- 可对照 Agent OS：是否同时具备场景、数据、方法论、Skill、试点五块，而不是只堆模型。
