# 需求管理

科学园 Agent 项目的需求资料统一存放于此。初始清单来自《科学园Agent实施排期表》，已按统一字段吸收整理，便于后续增删改查与排期跟踪。

## 目录结构

```text
需求管理/
├── README.md              # 本说明（管理规范）
├── 需求总览.md            # 看板：按状态/优先级/大类速览
├── 需求清单.md            # 完整需求明细（人工可读）
├── 需求清单.csv           # 完整需求明细（可导入表格/飞书多维表）
├── 变更记录.md            # 需求变更流水
└── 00-原始资料/           # 原始导入文件归档，不直接改
```

## 命名与编号

| 规则 | 说明 |
| --- | --- |
| 需求 ID | `REQ-001` … `REQ-033`（三位数字，与原表编号对应） |
| 新增需求 | 接续最大序号，如 `REQ-034`；不要复用已废弃编号 |
| 废弃需求 | 状态改为「已废弃」，保留记录，ID 不回收 |

## 字段说明

| 字段 | 含义 |
| --- | --- |
| 大类 | 六大业务域之一 |
| 技能套件 | 能力归属模块（如 OA办公、投研管理） |
| 技能名称 | Agent/技能对外名称 |
| 需求说明 | 做什么、覆盖哪些场景 |
| 典型交付结果 | 验收时可见的产出物 |
| 前置条件 / 状态 / 期望时间 | 依赖项是否具备 |
| 优先级 | P1 > P2 > P3 > P4 |
| 开发难度 | 一般 / 中等 / 复杂 |
| 预计完成时间 | 目标窗口（如 26年9月） |
| 实施状态 | 业务侧落地状态 |
| 开发进度 | 研发侧进度（来自原表开发跟踪） |
| 责任部门 / 对接人 | 业务 Owner |
| AgentOS配合事项 | 平台侧需配合的开发点 |

## 状态字典（统一用语）

**实施状态**

| 值 | 含义 |
| --- | --- |
| 可实施 | 前置条件基本具备，可排期启动 |
| 实施中 | 正在落地 |
| 试用中 | 已上线试用 |
| 阻塞-等待信息化建设 | 依赖信息化专项，暂不可推进 |
| 已完成 | 验收通过（后续补充） |
| 已废弃 | 明确不做 |

**开发进度**

| 值 | 含义 |
| --- | --- |
| 未排期 | 尚未进入研发排期 |
| 待开发 | 已确认要做，未开工 |
| 开发中 | 研发进行中 |
| 试用 | 研发侧已进入试用 |
| 已完成 | 研发交付完成 |

## 日常怎么用

1. **查进度 / 做周报**：先看 `需求总览.md`
2. **改需求内容**：改 `需求清单.md` 与 `需求清单.csv`（保持一致），并在 `变更记录.md` 记一笔
3. **新增需求**：分配新 `REQ-xxx`，补齐必填字段（大类、名称、说明、优先级、实施状态）
4. **原始 Excel**：只作归档；以本目录 Markdown/CSV 为准
